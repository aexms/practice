### Выпускная квалификационная работа (ВКР)

*2025 — 2026*

**Тема:** «Реализация и экспериментальное исследование алгоритмов разрежённого тензорного умножения и обобщённой (λ,μ)-свёртки на структуре Zip-Tree».

- Реализация на **Python** обобщённой **(λ,μ)-свёртки** для разрежённых тензоров в **Zip-Tree** с эталоном на плотных массивах **NumPy** (`einsum`).
- Алгоритмы **Кэннона** (последовательный и **параллельный** по процессам), **цепочки свёрток** с линейным порядком скобок и **оптимизация порядка (DP)**.
- **Воспроизводимый конвейер бенчмарков:** фиксация среды, повторы замеров, CSV; контроль **максимальной абсолютной погрешности** к плотному эталону.
- Анализ компромиссов между разрежённым хранением, накладными расходами параллелизма и выбором порядка операций на парах тензоров и цепочках.

**Стек:** Python, NumPy, модуль `practice/` (бенчмарки, отчёты по экспериментам).


## Структура модулей

| Модуль | Назначение |
|--------|------------|
| `ziptree_tensor.py` | Класс `ZipTreeTensor`, узлы дерева, операции над разрежённым тензором |
| `lambda_mu.py` | (λ,μ)-свёртка, эталон `lambda_mu_dense_numpy`, цепочки и DP-исполнение |
| `chain_optimize.py` | DP и исполнение оптимального порядка скобок для цепочки |
| `cannon_tensor.py` | Блочный Кэннон для свёртки, приведение к плотному виду |
| `cannon_parallel.py` | Параллельные фазы Кэннона (`ProcessPoolExecutor`) |
| `bench_*.py` | Точечные бенчмарки скорости (пары, цепочки, параллельное сравнение) |

## Результаты

Были реализованы следующие аспекты: хранение разреженного тензора в структуре
данных на основе Zip Tree, два варианта умножения (напрямую и с перестроением
второго дерева так, чтобы ось, по которой ведется умножение была первой), алгоритм
Кэннона и его обобщение на случай (λ, µ)-свернутого произведения, алгоритм
динамического программирования для выбора оптимальной последовательности
умножений цепочки тензоров, и его обобщение на случай (λ, µ)-свернутого произведения
многомерных матриц.
В случае с алгоритмами умножения, алгоритм с перестройкой второго дерева позволяет на
достаточно разреженных матрицах обгонять Numpy по скорости, но все еще значительно
уступает специализированным решениям для работы с разреженными данными, такими
как torch.sparse. Обычное умножение крайне неэффективно в силу того, что при
умножении приходится полностью обходить второе дерево, для каждого ненулевого
элемента в первом тензоре.
Использование алгоритмов выбора оптимального порядка умножения нескольких
многомерных матриц не показали прироста в быстродействии, скорее всего из-за того, что
из-за работы с сильно разреженными объектами гораздо важнее снижение числа
ненулевых элементов в промежуточном результате, чем порядок умножения, особенно, в
случае если размерности всех операндов близки.
Реализация алгоритмов для параллельной обработки также не принесла улучшения
скорости ввиду серьезных накладных расходов для распараллеливания при реализации с
помощью языка Python и относительно небольших размеров блоков, получаемых в
тестируемых примерах.
