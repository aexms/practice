### Выпускная квалификационная работа (ВКР)

*2025 — 2026*

**Тема:** «Алгебраические модели и методы проектирования для алгебр разреженных многомерных матриц».

*Реализация и экспериментальное исследование алгоритмов разрежённого тензорного умножения и обобщённой (λ,μ)-свёртки на структуре Zip-Tree*

Проект предлагает **Python-решение** для эффективной работы с разрежёнными тензорами произвольной размерности. В отличие от плотных `numpy.einsum` и специализированных библиотек (`torch.sparse`, `scipy.sparse`), наш подход:

- использует **Zip-Tree** — вероятностную структуру данных с логарифмической сложностью операций;
- реализует **обобщённую (λ,μ)-свёртку** — гибкий аналог тензорного умножения с настройкой осей;
- включает **блочный алгоритм Кэннона** (последовательный и параллельный) для распределённых вычислений;
- оптимизирует **цепочки свёрток** через динамическое программирование.

Главная ценность работы — **полный контроль над компромиссами**: разреженность vs. накладные расходы, последовательная vs. параллельная обработка, порядок операций vs. размер промежуточных данных.

## Результаты

В ходе экспериментального исследования были получены следующие результаты:

| № | Результат |
|---|-----------|
| 1 | **Алгоритм с перестройкой второго дерева** (подготовка оси умножения) на сильно разреженных тензорах (плотность < 10⁻³) **обгоняет плотное умножение NumPy (einsum) в 1.5–2 раза** по времени. Это достигнуто за счёт сокращения числа обходов дерева. |
| 2 | **Наивное прямое умножение** (без перестройки) неэффективно: оно требует полного сканирования второго операнда для каждого ненулевого элемента первого — квадратичная зависимость от числа ненулевых элементов. |
| 3 | **Оптимизация порядка умножения цепочки (DP)** не дала прироста скорости для наших тестовых сценариев. **Причина:** для сильно разрежённых объектов ключевой фактор — минимизация числа ненулевых элементов в промежуточных результатах, а не порядок ассоциации. Этот **отрицательный результат является ценным инсайтом** для практиков. |
| 4 | **Параллельный алгоритм Кэннона** на Python (`ProcessPoolExecutor`) не улучшил производительность на тестовых размерах блоков (до 10⁵ элементов). **Накладные расходы** на межпроцессное взаимодействие и сериализацию перевешивают выгоду от параллелизма. **Порог эффективности** определён: размер блока должен быть ≥ 10⁶ ненулевых элементов. |
| 5 | Разработан **воспроизводимый конвейер бенчмарков** (фиксация окружения, повторы, CSV-логи, контроль погрешности до 1e-10). Это позволяет сравнивать алгоритмы в одинаковых условиях и верифицировать корректность относительно плотного эталона. |


## Стек технологий

- **Python 3.10+** — основной язык
- **NumPy** — плотный эталон и вспомогательные операции
- **concurrent.futures** — параллельные фазы Кэннона
- **pytest / timeit** — бенчмарки
- **Jupyter Notebook** — визуализация результатов

Все модули самодостаточны, не требуют установки дополнительных пакетов (кроме стандартной научной экосистемы).

## Структура модулей

| Модуль | Назначение |
|--------|------------|
| `ziptree_tensor.py` | Класс `ZipTreeTensor` — разрежённый тензор на Zip-Tree, базовые операции |
| `lambda_mu.py` | (λ,μ)-свёртка, плотный эталон (`lambda_mu_dense_numpy`), цепочки и их исполнение |
| `chain_optimize.py` | Динамическое программирование для выбора оптимального порядка свёрток |
| `cannon_tensor.py` | Блочный алгоритм Кэннона для свёртки (последовательная версия) |
| `cannon_parallel.py` | Параллельный Кэннон через пул процессов |
| `bench_*.py` | Скоростные бенчмарки: пары тензоров, цепочки, параллельное сравнение |
